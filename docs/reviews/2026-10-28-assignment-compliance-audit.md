# Algorithm Visualization — 과제 요구사항 및 정확성 감사

감사일: 2026-10-28. 기준: dev `708bf22b6ee7af7256030b269f740644b4cbe27d`. 이번 시각 보완은 배너 Y/Fade와 최종 비MST 선 opacity에 한정한다. 감사 대상인 알고리즘·Snapshot·기존 알고리즘 테스트·`docs/mst-core.md`는 변경하지 않았다.

## 결론

**일부 요구사항 미충족 또는 확인 필요**

검토·테스트 범위에서 알고리즘 정확성 결함이나 GSAP에 의한 확정 결과 왜곡은 발견하지 못했다. 최종 PDF, 배포 URL, 제출용 캡처의 완성·포함 여부와 강의에서 비교하지 않은 조합인지의 확인이 남았다. 이 항목들은 애니메이션 결함과 구분한다.

평가 기준은 사용자가 제공한 12항목이다. 교수님의 원문 과제지·강의 비교 목록은 제공되지 않았으므로 그 이상의 형식/분량 조건이나 조합 승인을 추정하지 않았다. 저장소 밖의 파일·외부 배포 존재 여부는 확인하지 않았다.

## 4. Definition / Procedure / 복잡도 일치성

- 공통 입력은 단순 무방향 연결 가중치 그래프이다. 유한 number의 0/음수/소수 허용, 중복 간선·자기 루프·잘못된 끝점·오버플로·비연결 입력 오류가 문서와 코드에서 일치한다.
- `graph.ts:86`의 정렬은 가중치 방향만 반전하고 이름·ID 동률 기준은 항상 오름차순이다. 문서의 공통 정렬 설명이 이를 포함한다.
- `graph.ts:96`의 인접 리스트 BFS는 visited Set과 head 인덱스 큐를 사용하여 O(V+Eₐ)이다. shift의 배열 이동이나 추가 UI 연결성 판정은 없다.
- `snapshot.ts:12`는 매 기록마다 모든 간선 상태를 복사·freeze하고 활성 ID/합/연결 요소를 보관한다. 입력과 결과는 불변이며 GSAP이 수정하지 않는다.

V=정점, E=간선, T=Kruskal 검사 간선 수, Sₖ=1+T, Sᵣ=1+2E. 문서처럼 문자열 길이는 상수, Map/Set은 평균 O(1), V8 비교 정렬 비용을 가정한다.

| 대상 | 기록 제외 핵심 시간(검증 포함) | 기록 포함 실제 시간 | 추가 메모리 |
|---|---|---|---|
| Kruskal | O(V log V + E log E + T α(V)) | O(V log V + E log E + T α(V) + Sₖ(V+E)) | 작업 O(V+E), 기록 O(Sₖ(V+E)) |
| Reverse-Delete | O(V log V + E log E + E(V+E)) | O(V log V + E log E + Sᵣ(V+E)) | 작업 O(V+E), 기록 O(Sᵣ(V+E)) |

Basic Operation은 정렬 비교, UF의 find/union, BFS의 정점·인접 간선 방문이다. 실제 캡처의 전체 상태 복사·합산·BFS·freeze도 시간/공간에 포함한다. UF만 O(V)이지만 정규화/정렬 복사본/상태 Map을 포함한 구현의 작업 공간은 O(V+E)다. 모든 기록은 최악 O(E(V+E)) 공간이다.

RD 임시 기록의 BFS와 핵심 연결성 검사는 같은 연산이므로 중복 가산하지 않는다. 이 입력에서 캡처 BFS는 15회, 공통 사전 검증 BFS는 1회다. 문서의 코어 114개 테스트 표기는 Phase 2 검증 이력이며 현재 전체 테스트 수와 혼동하지 않는다.

## 5. GSAP이 결과를 왜곡하는지

`useEdgeTransition.ts:23`·`:50`·`:161`에서 대상과 확정 단계를 분리한다. commit 콜백(`:129`)에서 React 확정 index를 갱신하기 전에는 정적 그래프·표·설명·합·연결 요소가 이전 스냅샷을 표시하고, 진행 문구에 이를 명시한다. 이동 시 기존 실행을 generation 번호로 무효화한다. 시각 종료와 읽기 대기를 분리하고 원본 style/transform을 복원한다.

이번 0.35 opacity는 `GraphView.tsx:43`의 graph-edge SVG 속성에만 적용한다. `AlgorithmPanel.tsx:68`에서 받은 MstRun.mst의 ID를 사용한다. 그룹/배지/정점/간선 데이터는 변경하지 않으며 pending/rejected/removed 점선과 표를 유지한다. 선택/유지 색이 다르다는 이유로 MST 소속을 오판하지 않는다. 비MST를 숨기거나 삭제하지 않는다.

신규 `finishVisualAudit.test.tsx`의 6개 시퀀스 검사는 두 알고리즘의 모든 스냅샷을 직접 선택·Next 완료·자동 재생 완료 경로에서 대조한다. 기대 간선 판정/합/연결 요소는 손으로 확인한 표이며 구현의 정렬/BFS/UF를 정답 계산에 재사용하지 않는다. 실제 기록과 DOM의 상태·점선·설명·활성 수·최종 opacity 및 MST 결과를 검증한다. 기존 코어의 독립 완전탐색 최적성 검사도 보존했다.

현재 테스트와 읽기 전용 검토에서 구체적인 정확성 결함은 발견하지 못했으므로 결함 재현 절차는 없다. 이는 임의의 모든 입력 또는 실제 브라우저의 중간 페인팅/접근성까지 증명했다는 의미가 아니다.

## 6. 제출 전 반드시 남은 작업

1. **수업 적합성 확인:** 두 알고리즘 조합이 수업에서 직접 비교한 조합인지 확인한다.
2. **최종 PDF 1개:** Definition 4항목·Procedure·Basic Operation·시간/공간 비교·실행 이유·동률 유의사항을 포함한다. 이번에는 제작하지 않는다.
3. **공개 배포 URL:** 실제 접속 가능한 주소를 확보·검증하고 PDF에 포함한다. localhost는 배포 주소가 아니다. 이번에는 배포하지 않는다.
4. **최종 화면 3~5장:** 최종 UI 기준으로 초기 비교, AC 기각, BE 임시 제거/복구, 최종 MST 등 핵심 장면을 선정해 읽을 수 있는 해상도로 PDF에 포함한다. 기존 외부 캡처를 재사용한다면 현재 버전과 일치하는지 확인한다.
5. **수동 시각/접근성:** 아래 장면 및 1440/390/320px, 200%, 키보드, Reduced Motion, 콘솔, 스크린리더 공지를 확인한다.

## 7. 검증 결과와 한계 / 수동 시연

기준 206개에서 기존 테스트 삭제·수정 없이 신규 17개를 추가하여 **10개 파일 223개 테스트 PASS**를 확인했다. build/lint/diff check도 통과했다. 신규 11개는 배너/간선 표현·정리·변형 MST를, 신규 6개는 전체 스냅샷 경로를 검증한다. 별도 읽기 전용 감사 결과를 작성자가 실제 소스와 대조했다.

실제 브라우저 화면 검증은 수행하지 않았다. 이전 Windows 브라우저 URL 확인 실패에 따른 Computer Use 안전 중단을 재시도/우회하지 않는다. DOM/GSAP 성공은 화면 가독성·접근성 PASS가 아니다.

수동 녹화: localhost 개발 서버를 열어 초기 등장 완료 후 (1) Kruskal 4단계→다음/재생, (2) RD 13단계→다음/재생을 각각 촬영한다. Bloom 뒤 배너의 아래→위 등장, AC/CD/DE 선만 흐려지고 가중치는 선명한지, Previous/Restart에서 선이 복원되는지, 직접 마지막 선택 시 이동 없이 정확한 결과를 표시하는지 확인한다. 0.5배속에서 Pause/Resume·직접 이동·다시 재생의 잔상도 확인한다.

이번 감사는 위 누락의 추가 기능 구현·PDF·배포·Push를 승인하거나 수행한 것이 아니다.
