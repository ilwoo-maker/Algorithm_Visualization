# Phase 3B-2 Cinematic Playback Design

## 승인된 목표와 범위

밝은 대시보드·어두운 SVG 무대와 기존 스냅샷 기록을 유지한다. 검사(Focus) → 판정(Decision) → 확정(Settle)을 거쳐 결과를 공개하고 각 패널에 재생·일시정지·계속 재생·다시 시작·0.5/1/2배속을 제공한다. 알고리즘 코어, 기존 알고리즘 테스트, CI, 의존성은 변경하지 않는다. 그래프 편집·공동 재생·확대/전체 화면·배포는 제외한다. 현재 dev에서 기존 두 로컬 커밋을 보존하고 로컬 커밋만 생성한다.

## 기존 구조와 선택한 접근

AlgorithmPanel이 탐색 인덱스를 소유하고 GraphView의 useEdgeTransition이 이미 변경된 스냅샷 위에 효과를 얹는다. scopedTimeline은 GSAP context로 완료/취소 시 임시 스타일을 복원한다. graphEntrance와 최종 MST 효과를 재사용한다.

채택: 패널의 useAlgorithmPlayback 소유자가 확정 index, 전환 targetIndex, phase, 재생 status, speed와 단일 GSAP 실행을 관리한다. GraphView는 확정 snapshot을 렌더링하고 대상 간선에만 장식 레이어를 제공한다. 고정 간격 타이머 방식은 완료 시점과 설명이 어긋나므로 사용하지 않는다. 별도 그래프 복제/알고리즘 재계산도 하지 않는다.

## 일관성 계약

- 전환 중 표·설명·가중치·연결 요소·정적 SVG는 마지막 확정 snapshot이다. 진행 표시에 대상 간선과 확정 전임을 명시한다.
- Focus 0–0.3초, Decision 0.3–0.7초, Settle 0.7–1.1초. 마지막 확정 지점에 React 표시를 한 번에 갱신한다. 수치는 보간하지 않는다.
- Kruskal은 Draw/짧은 Reject shake, Reverse-Delete는 중앙 절단/중립 삭제/청색 복구를 사용한다. 움직임은 방향성이나 새로운 계산 상태가 아니다.
- 완료 효과는 확정 이후 MstRun.mst와 totalWeight에서 읽는다. 최종 가중치는 고정 숫자다.

## 재생·수명 규칙

타임라인 완료 후에만 다음 인접 전환을 요청한다. 읽기 대기는 같은 타임라인에 포함하며 1배속 1.3초를 기본값으로 한다. 속도는 timeScale 하나로 전환과 대기 모두에 적용한다. Pause는 현 위치를 보존하고 Resume은 같은 타임라인을 재개한다. Restart는 0단계 대기 상태다. 마지막 Play는 0부터 재생한다.

빠른 Next는 기존 대상을 즉시 확정한 뒤 그 다음 대상으로 전환하므로 클릭마다 목적 단계가 하나 증가한다. 이전/처음/직접 선택은 즉시 확정한다. 직접 선택창을 열기만 해도 현재 확정 단계에서 자동 재생과 효과를 취소한다. 취소 세대 번호로 늦은 콜백을 무시한다. 패널별 소유권을 격리하고 StrictMode 정리·unmount 시 context를 복원한다.

탭이 숨겨지면 현재 실행을 Pause하고 돌아와도 직접 Resume이 필요하다. Reduced Motion은 장식 없이 확정하되 읽기 대기로 순차 진행한다. 실행 중 설정 변경도 정리한다.

## 검증 한계

149개 기준 테스트의 검증 의도는 유지하고 확정 시점 변경에 따른 기대 시점만 조정한다. 실제 GSAP 타임라인을 명시적으로 진행시켜 DOM·경합·정리 동작을 검증한다. DOM 검증은 브라우저 페인팅 품질 검증이 아니다. 이전 Computer Use 안전 중단을 우회하지 않으며 1440/390/320px, 200%, 키보드·콘솔·실제 Reduced Motion은 수동 검토로 남긴다.
