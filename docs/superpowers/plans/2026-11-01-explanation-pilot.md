# 단계별 설명 보강 시범 적용 계획

목표: 승인된 대표 장면(AC 기각, BE 임시 제거·복구)과 효율성 비교를 구체적이고 자연스럽게 설명한다.

설계: 원본 Snapshot.what/why와 코어는 보존한다. 표시 계층에서 과제 입력과 해당 상태가 확인되는 경우에만 경로·이전 상태를 설명하는 보충 문장을 제공한다. 다른 입력은 원본 설명만 표시한다. 새 연결성·경로 탐색은 구현하지 않는다.

대안: 코어의 설명을 직접 교체하면 범용 알고리즘과 과제 전용 해설이 섞인다. 따라서 이번에는 화면 보충 해설을 선택한다. 모든 문구의 일괄 수정은 다음 검토로 남긴다.

- [x] 대표 장면의 화면 설명, 다른 입력에 적용되지 않음, 입력 불변성을 테스트한다.
- [x] 설명 전용 모듈과 Lab·개념 예시 표시를 연결한다. What/Why 원문은 유지한다.
- [x] 강의용 문서의 효율성 요약을 작업 차이 → 시간 근거 → 공간 조건 순으로 다듬는다.
- [x] 전체 테스트·빌드·린트·공백 검사 및 변경 범위를 확인한다.

제약: 코어·기존 알고리즘 테스트·계산·재생·레이아웃·의사코드·복잡도 수식은 변경하지 않는다. commit/push 없음. 실제 브라우저 가독성은 별도 미확인이다.

검증 결과: 기존 272개 유지, 신규 4개로 19개 파일 276개 PASS. build/lint/diff check 성공. 기존 이론 UI 테스트의 옛 문장 기대값을 새 표현 및 BFS 근거로 갱신했다. src/algorithms 변경 없음. 원본 이유를 유지한 보충 해설 방식이라 화면 높이가 늘며 실제 읽기 부담은 사용자 검토가 필요하다.
